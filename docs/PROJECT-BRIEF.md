## 2. 專案初衷

Banson 是集團 CEO，六個事業體的營運資訊分散在各主管口頭彙報與人工報表中，沒有統一視圖。已知痛點：

- **月結太慢**：單一會計負責六個 BU 帳務，月結平均 12 個工作天，經營決策靠過期數字
- **人事風險不透明**：主管暫代未轉正（許舒婷）、設計師跨部門兼職過勞（陳又暐）、行銷部整編制空缺——這些風險存在大家腦中，沒有制度化追蹤
- **信義店的結構性問題**：5 人團隊對 5,000 萬目標，人均產值需求遠超業界水準，需要數據支撐「補人 / 調目標 / 改模式」的三選一決策
- **原物料通膨**：鋁料年初至今 +40%、板材 +38%，既有固定價合約毛利被壓縮，需要趨勢可視化

儀表板的初衷不是「做一個漂亮的報表」，而是**建立集團用數據對話的習慣**——V1 用假資料把「容器」做好，讓團隊先習慣看燈號、看進度、認領風險，2026 下半年逐步灌入真數字。

### 3.2 技術現況

**技術棧**：Next.js 14.2（App Router、TypeScript）、Tailwind CSS（CSS 變數驅動、`next-themes` 明暗雙主題）、Recharts、Zustand（僅 UI 狀態）、date-fns、Noto Sans TC + Inter。

**部署**：Vercel（免費 Hobby），production branch = `main`，push 即自動部署，約 1–2 分鐘生效。

**關鍵架構決策**（後續開發者必讀）：

1. **`lib/data/index.ts` 是唯一資料介面**。所有頁面透過 async fetcher（`fetchBusinessUnits()`、`fetchCashFlow()`…）取數，回傳「顯示就緒」的 view model（BU 名稱已解析）。`app/` 與 `components/` **禁止直接 import `lib/mock`**。階段三接真 API 只改這一個檔案。
2. **所有 widget 是純 props 元件**，頁面是 async server component，server 端取數後下傳。
3. **Mock 數字結構性自洽**：`activeProjects` 由專案清單推導、現金流由損益表推導（收現率 93%、費用比例拆分）、期末現金由累加算出——改一處不會產生跨頁矛盾。
4. **報表基準日集中於 `lib/report-date.ts`**（`2026-05-25`）：所有日期用本地時區安全的 `parseDateOnly`/`formatMonthDay`，避免 SSR/CSR hydration mismatch 與西半球時區日期偏移。
5. **UI 語意集中**：`lib/ui/severity.ts`（嚴重度/狀態→色彩）、`lib/ui/chart-colors.ts`（BU 識別色、原物料色）。顏色不放在資料型別裡（真 API 不會回傳顏色）。
6. **P&L 用比率反推**：各 BU 設 `costRate`/`opexRate`（`lib/mock/finance-data.ts` 的 `PNL_RATIO`），由月營收算出成本毛利。這表示每月毛利率固定——是 mock 的已知簡化。

**檔案結構**：
```
app/(dashboard)/        # layout（側欄）+ 5 個頁面（全部 async RSC）
  page.tsx              # 集團總覽
  bu/[buId]/page.tsx    # BU 詳情（SSG，6 條路徑）
  finance/ people/ risk/
components/layout/      # Sidebar, TopBar
components/widgets/     # 14 個純 props 元件（KpiCard, BuMatrix, RiskMatrix, OrgChart, CashFlowWaterfall...）
components/ui/          # shadcn 風格 Card / Button
lib/data/index.ts       # ★ 資料存取層（換 API 的唯一接縫）
lib/mock/               # 6 個假資料檔（bu / revenue / finance / project / org / risk）
lib/ui/                 # severity.ts, chart-colors.ts
lib/report-date.ts      # ★ 全站報表基準日
lib/types/index.ts      # 全部 domain 型別
store/dashboard-store.ts # Zustand：僅側欄開合等 UI 狀態
```

## 4. 目前的問題與卡點

### 4.1 需要 CEO 動作的
- **Mock 數字未經校準**：所有金額、比率、風險評分都是 AI 依常理編造，未經任何真實帳務驗證。Demo 給團隊前必須過一輪 CEO 的眼睛，否則工具第一印象的可信度會受損
- **4 點上線驗收未回報**：部署後請 CEO 確認的檢查（KPI=18、信義紅燈頁、瀑布 3,404 萬、暗色切換）尚未收到確認

### 4.2 環境限制（開發 AI 側）
- 開發 AI 的沙箱網路無法連 `*.vercel.app`（proxy 403），**線上站的驗證只能靠 CEO 或另行想辦法**；本地 build + 截圖驗證不受影響
- 開發環境是 ephemeral 容器，會重啟；所有成果以 push 到 GitHub 為準（已養成習慣，無未推送的工作）

### 4.3 已知但有意保留的技術債
1. `destructive` 與 `danger` 雙色票並存（CSS 值相同，純命名債，零使用者影響）
2. Recharts 圖表對螢幕閱讀器只有 aria-label 摘要，無完整資料表替代（等真資料再做）
3. 組織圖是純 CSS 樹而非 React Flow（20 人規模夠用；人數 >50 或需拖拉編輯時再換）
4. AR Aging 總額（2,450 萬）與現金流收現率（93%）未完全閉環——mock 未建模「期初應收」，兩者數字獨立合理但無法互相推導
5. 人數口徑：組織圖只涵蓋總部＋設計體系 4 部門（31 編制/21 在職）；好室/Wayhome/Homatch 的 12 人直屬各 BU 不在組織圖中（頁面已加文字說明，但資料模型未統一）

GitHub `main` 分支已建立並設為 default、Vercel 自動部署已通、先前唯一的硬卡點（無 main 分支開不了 PR）已解除。
